# CandleAlerts

A React Native app built with Expo that schedules candle-close alarms on Android. Generate alert times based on candlestick chart intervals and schedule them either as app-owned alarms (instant, background, rings like a clock alarm) or as one-off alarms in the device Clock app.

## Overview

CandleAlerts helps traders set a batch of one-off alarms for candle-forming times in technical analysis. Configure a candle interval (e.g., 15 minutes), a lead time before the candle forms (e.g., 2 minutes), and how many upcoming candles to track. The app generates alert times and schedules them in one of two alarm modes.

## Features

- **Generate candle alerts** — Compute upcoming candle-forming times based on interval, lead time, count, and an optional start time
- **Two alarm modes** (Settings → Alarm mode):
  - **CandleAlerts (default)** — App-owned alarms registered with `AlarmManager.setAlarmClock`. A batch is created instantly and works in the background, so you can switch apps right after tapping Set Alarms. Alarms ring and vibrate through the app's own foreground service, with a lock-screen alarm UI and Snooze/Dismiss. Pending alarms are listed in the app and can be cancelled individually or all at once, and they are re-registered after a reboot.
  - **Clock app** — Alarms are created in the stock Clock app via Android's AlarmClock API. The app must stay open (about 3 seconds per alarm), and the Clock app owns the alarms afterward.
- **Configurable defaults** — Interval, lead, count, same-day filter, and snooze minutes (1–60, App mode only) can be saved in Settings
- **Reliability helpers** — In App mode, Settings shows shortcuts to allow full-screen alarms and disable battery optimization
- **Same-day filter** — Optionally limit alerts to today only (off by default)

## Tech Stack

- **Expo SDK 57** with React 19 and React Native 0.86
- **Expo Router** — File-based navigation
- **TypeScript** with strict mode
- **Custom native module** — Android alarm scheduling via `NativeAlarmModule` and supporting Kotlin classes, generated by a config plugin
- **AsyncStorage** — Persists saved defaults and the selected alarm mode

## Get Started

### Prerequisites

- Node.js 20+
- npm or yarn
- Android device or emulator (iOS not currently supported)
- Android SDK and JDK 17 for local builds
- A development build: the custom native module means Expo Go cannot run this app

### Install

```bash
npm install
```

### Run

```bash
npx expo run:android      # builds, installs, and starts the dev build
npx expo start --dev-client   # start Metro for an installed dev build
```

Alarm scheduling only works on Android. The web and iOS targets do not support it.

### Build for Production

```bash
# Development build
npx eas build --profile development

# Preview (APK)
npx eas build --profile preview

# Production (AAB)
npx eas build --profile production
```

## Usage

1. Optionally open **Edit defaults** to set the alarm mode, snooze minutes, and default values
2. On the main screen set your preferences:
   - **Interval (min)** — Candle size in minutes (e.g., 15, 30, 60)
   - **Lead (min)** — Minutes before the candle forms to alert (e.g., 2)
   - **Count** — How many upcoming alerts to generate
   - **Same day only** — Toggle to restrict alerts to today
   - **Start time** — Optional time to start from (defaults to now)
3. Tap **Generate Alerts** to preview upcoming alert times
4. Tap **Set Alarms**
   - **App mode**: grant the notification and "Alarms & reminders" permissions when asked. Alarms are scheduled instantly and listed under **Scheduled Alarms**, where you can cancel them.
   - **Clock app mode**: keep the app open while alarms are sent, then tap **Open Clock App** to confirm they were created

## Architecture

### Alert Generation (`candleAlerts.ts`)

Pure TypeScript logic with no platform dependencies. Computes alert times by:

1. Finding the next candle boundary after the current time (based on interval)
2. Subtracting the lead time to get the alert time
3. Generating up to `count` alerts, optionally restricted to the same day

This module is fully testable in plain Node.js.

### Alarm Scheduling (`alarmSchedulerCore.ts`)

A facade pattern decouples the UI from the platform implementation:

- `setAlarmScheduler()` / `getAlarmScheduler()` — Register/retrieve the active implementation (chosen from the saved alarm mode)
- `scheduleCandleAlerts(alerts)` — Schedule the generated batch
- `capabilities` — `background` and `manageAlarms` flags the UI uses to show hints and the scheduled-alarms list
- Optional `ensurePermissions()`, `listPending()`, `cancel()`, `cancelAll()` for App mode
- `openClockApp()` — Launch the Clock app's alarm list (Clock mode)

### App mode (`appAlarmScheduler.ts` + native Kotlin)

- `NativeAlarmModule.scheduleBatch` stores each alarm (SharedPreferences) and registers it with `AlarmManager.setAlarmClock`, which is exempt from Doze and feeds the system "next alarm" indicator. Absolute timestamps mean the 24-hour limit of Clock mode does not apply.
- `AlarmReceiver` starts `AlarmRingService`, a foreground service that loops the default alarm ringtone on the alarm audio stream, vibrates, and posts a full-screen notification with Snooze and Dismiss. `AlarmRingActivity` is the lock-screen UI. Ringing stops by itself after 5 minutes.
- `BootReceiver` re-registers future alarms after a reboot or app update.
- Snooze uses the saved `snoozeMinutes` value.
- If full-screen permission is missing, alarms still ring but do not take over a locked screen. Aggressive OEM battery managers can delay or cancel alarms unless battery optimization is disabled for the app.

### Clock app mode (`alarmScheduler.android.ts`)

Wraps `AlarmClock.ACTION_SET_ALARM` for silent alarm creation and `AlarmClock.ACTION_SHOW_ALARMS` to open the Clock app. The intent API accepts only an hour and minute, so CandleAlerts rejects alerts that are not within the next 24 hours (the Clock app sets the next occurrence of that time, so alerts crossing midnight work). Each launch is paced by 3 seconds in the native module because faster bursts make the Clock app drop alarms.

### Config plugin (`withCandleAlertsNative.ts`)

An Expo config plugin that:

1. Writes the Kotlin sources (`NativeAlarmModule.kt`, `NativeAlarmPackage.kt`, and the app-alarm classes from `native-templates/`) into the Android project
2. Adds permissions, intent visibility queries, and the service, receivers, and activity to `AndroidManifest.xml`
3. Adds `NativeAlarmPackage` to the React package list

The plugin reads the Kotlin templates with `fs` because the config plugin loader cannot resolve relative TypeScript imports.

### iOS

iOS alarm scheduling is not yet implemented. The iOS stub throws descriptive errors and the UI shows "iOS not supported yet" in the footer. See [ios-implementation-plan.md](./ios-implementation-plan.md) for the planned approach.

## Development Notes

- **Native code**: After modifying `withCandleAlertsNative.ts` or the files in `native-templates/`, run `npx expo prebuild` or rebuild via EAS Build to regenerate native files
- **Tests**: `npm test` runs the pure-logic tests (alert generation, defaults, alarm mode) in Node.js
- **Checks**: `npm run lint` and `npx tsc --noEmit`
- **Manual testing**: Follow [test-instructions.md](./test-instructions.md) for the device-level test plan
- **Alarms don't transfer between modes**: Clock-mode alarms are owned by the Clock app and App-mode alarms live only in this app
- **No iOS support yet**: The iOS scheduler stub and UI footer communicate this clearly
